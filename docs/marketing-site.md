# ThreatLint public marketing site

This folder contains the **static public website**, separate from the Node/Express Workbench in `web/` and the Python code in `src/`. Do not point a public static hosting service at `web/` or expose local Workbench endpoints.

## Cloudflare Pages deployment

In Cloudflare Dashboard → Workers & Pages → Create application → Pages → Connect to Git:

| Setting | Value |
| --- | --- |
| GitHub repository | `h0p3sf4ll/threatlint` |
| Production branch | `main` |
| Framework preset | None |
| Root directory (advanced) | `marketing` |
| Build command | `exit 0` (or leave blank) |
| Build output directory | `.` |
| Environment variables | None |

Select Save and Deploy. After the `*.pages.dev` preview succeeds, go to Pages project → Custom domains → Set up a domain → `threatlint.dev`.

For an apex domain, Cloudflare requires your domain to be an active Cloudflare DNS zone. Set your registrar's nameservers to the **exact** two nameservers given in your Cloudflare dashboard. Do not erase existing MX, SPF, DKIM, or DMARC records if you use email on the domain. Once HTTPS is active, optionally add `www.threatlint.dev` as another custom domain and redirect it to the apex.

## Local preview

Run a simple static server from this folder:

```bash
cd marketing
python3 -m http.server 8000
```

Then open `http://localhost:8000`. No API keys, Node build, or backend are needed.

The page contains an explicitly synthetic example; it is not a report generated by running ThreatLint. Review public claims and calls to action before promoting the site. Any changes committed to `main` are deployed automatically after connecting Git integration.
